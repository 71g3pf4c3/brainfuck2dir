# brainfuck2dir

[![CI](https://github.com/71g3pf4c3/brainfuck2dir/actions/workflows/ci.yml/badge.svg)](https://github.com/71g3pf4c3/brainfuck2dir/actions/workflows/ci.yml)

Brainfuck source as directory trees. Runs of a command become files,
loops become directories:

```
$ b2d -- '++[->+<].'
{"001+": "002","002loop": {"001-": "001","002>": "001","003+": "001","004<": "001"},"003.": "001"}

$ b2d -o tree '++[->+<].'
$ find tree | sort
tree
tree/001+
tree/002loop
tree/002loop/001-
tree/002loop/002>
tree/002loop/003+
tree/002loop/004<
tree/003.
```

File `001+` contains `002`: entry 1, command `+`, run length 2.
Directory `002loop` is entry 2, a `[...]` block. Reconstruction is
`find | sort` and a for loop. You did not need this. Neither did the
tree.

## The part that matters

**The converter is brainfuck.** Not "inspired by". Not "a fun DSL".
`src/b2d.bf` is ~98KB of `+ - < > . , [ ]` that reads brainfuck on
stdin and emits single-line json2dir-scheme JSON on stdout. Run-length
encoding, sequence numbering, nesting, the comma placement — all of it
is brackets and pointer shuffling on a 30000-cell tape, generated by
`tools/gen_b2d.py` (a brainfuck macro assembler with symbolic pointer
tracking, because writing 98KB by hand is where we draw the line).

The Zig binary is honest about its role: a VM, a CLI, and a
materializer borrowed from [json2dir-zig]. The thinking happens in
brainfuck. The boring parts happen in Zig. As nature intended.

Some implementation details you can unsee but not unlearn:

* the frame stack is a runtime quantity, so generated code cannot bake
  the nesting level into addresses. The active frame lives at fixed
  cells; `[` pushes it onto a stack of 4-cell slots, `]` pops it back.
  Slot cells are always nonzero and everything past the top is zero,
  which is why `go(64) [>]` lands exactly on the next free slot and
  `[<]` walks home through the sentinel;
* the dispatcher compares the input byte against each command char via
  `d = in - K` with a destructive single-shot guard, so a comment byte
  costs O(1) per comparison instead of O(byte value);
* a run of 999 is the cap; the 1000th repetition starts a new entry.
  The converter flushes the 999-run and zeroes the pending command, so
  you get `"999"` + `"001"`, not `"999"` + `"002"`. We tested this. We
  had to. It was wrong once.

## Usage

```
Usage: b2d [OPTIONS] [FILE]

  -o, --out <DIR>    Materialize into DIR instead of printing JSON.
  -n, --dry-run      Validate and print the plan; write nothing.
  -v, --verbose      Print one line per entry while applying.
      --no-clobber   Fail instead of replacing existing entries.
  -h, --help         Print this help and exit.
  -V, --version      Print version and exit.
```

Input is validated before the interpreter runs: NUL bytes (0 is the
EOF marker on the brainfuck tape), unbalanced brackets, nesting deeper
than 7400 loops, and more than 999 entries per level are rejected with
exit code 2. Yes, there is a NixOS module. No, that does not make this
production-ready. See `docs/b2d.1` for the full manual.

## Install

Nix (static musl binaries, no toolchain, no sysroot):

```
nix run github:71g3pf4c3/brainfuck2dir -- examples/hello.bf
```

NixOS / home-manager:

```nix
# flake input: brainfuck2dir.url = "github:71g3pf4c3/brainfuck2dir";
programs.b2d.enable = true;
```

From source, if you enjoy compiling:

```
zig build install
```

## Development

```
zig build test                       # unit tests, golden conversions
nix flake check --all-systems        # tests + b2d.bf regen check + smoke
python3 tools/gen_b2d.py > src/b2d.bf   # regenerate the converter
```

`src/b2d.bf` is generated and checked in; a flake check fails if it
drifts from the generator. Editing brainfuck by hand is possible in the
same sense that performing your own appendectomy is possible.

## Why

Because [json2dir] exists, and someone had to ask what happens if the
JSON is produced by a brainfuck program. The answer is: a directory
tree, correctly, with atomic writes. You're welcome.
